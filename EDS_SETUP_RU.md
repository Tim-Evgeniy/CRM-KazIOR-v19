# Выбор ключа ЭЦП и вход — v17

В v17 «Войти с ЭЦП» открывает отдельное окно с кнопкой **«Выбрать ключ с компьютера»**. Дальше открывается файловое хранилище NCALayer: пользователь выбирает свой `.p12` или `.pfx` и вводит пароль в NCALayer. Закрытый ключ и пароль не передаются CRM. Подписанный запрос проверяется на сервере.

## Запуск на одном компьютере

1. Установите и запустите [NCALayer от НУЦ РК](https://pki.gov.kz/ncalayer/).
2. На компьютере с сервером CRM установите и запустите Docker Desktop.
3. Запустите **START_EDS_SERVER.bat**. Он поднимает NCANode с доступом только через `127.0.0.1:14579`; кэш находится в Docker volume. Первый запуск загружает готовый образ и требует Интернет.
4. Откройте CRM под администратором → **Интеграции → ЭЦП**. Выберите **NCANode v3**, адрес `http://127.0.0.1:14579`, отметьте «Включить проверку ЭЦП» и сохраните.
5. Для инженера или администратора: войдите обычным способом → **Мой профиль → Привязать свою ЭЦП**. Выберите ключ и подтвердите запрос. Теперь «Войти с ЭЦП» откроет именно этот кабинет.
6. Новый сотрудник может сразу войти с проверенной ЭЦП: CRM создаст обычный кабинет, связанный с ИИН сертификата. Совпадение ФИО с инженером не выдаёт права инженера.

На сервере Linux: `docker compose -f server/eds-compose.yml up -d`. NCALayer устанавливается на рабочем компьютере подписанта, а NCANode — на машине с сервером CRM. Это разные приложения. Для NCALayer браузеру может потребоваться разрешение доступа к локальной сети.

## Что проверяет CRM

Используется [API NCANode](https://github.com/ncanode-kz/NCANode/blob/master/openapi.yml): `/cms/verify` с OCSP и `/cms/extract` для сравнения точных подписанных байтов. CRM требует положительного результата подписи и цепочки, одного подписанта, действующего сертификата, допустимого назначения ключа, подтверждения отсутствия отзыва и ИИН из сертификата. Ошибка сервиса или отсутствие проверки отзыва блокирует вход.

Запрос одноразовый, действует 5 минут, содержит случайное значение, адрес CRM и назначение операции. Повторно подтвердить его нельзя. Для документа также подписываются содержимое, версия и участники; изменение документа требует нового подписания. Браузерный вызов основан на [протоколе NCALayer](https://sigex-kz.github.io/ncalayer-js-client/api/NCALayerClient.html), модуль `kz.gov.pki.knca.basics`, метод `sign`, хранилище `PKCS12`.

Протокол NCANode v3 реализован в `server/ncanode_verifier.py`. Образ NCANode берётся из проекта разработчика, криптографический SDK не копируется в архив. В Compose используется тег `latest`; после проверки вашей версии можно заменить его точным тегом или digest. Проверка настоящим ключом пользователя и запуск Docker на его Windows в этой сессии не выполнялись.

## Если окно ключа не открывается

- Запустите NCALayer на том компьютере, где открыт браузер, и повторите выбор.
- Разрешите локальное соединение браузера с `wss://127.0.0.1:13579`.
- Если окно ключа открылось, но после подписи отображается ошибка NCANode, проверьте Docker, адрес сервиса и его исходящий доступ к службам НУЦ/OCSP.
- Если ключ привязан к другому кабинету, войдите в нужный кабинет обычным способом. CRM не объединяет кабинеты по совпавшему ФИО.

Выбор ключа доступен до настройки сервера проверки, но завершить вход без подтверждения подлинности нельзя. Закрытие окна выбора отменяет операцию.

## Тестовые документы

Раздел «Документы» остаётся отдельной тестовой страницей: создать → согласовать → подписать. Обычная кнопка тестовой подписи сохраняет демонстрационную отметку. CMS-подпись проверяется сервером; сам документ всё равно помечен как тестовый. Тестовая отметка не выдаётся за проверенную ЭЦП.

## Собственный адаптер вместо NCANode

Выберите «Собственный адаптер» и укажите полный URL проверки. CRM отправляет POST JSON с `cms`, `data` (Base64 точных байтов), `purpose` (`login`, `bind`, `document`), `requireRevocationCheck: true`. Если задан ключ сервиса, используется `Authorization: Bearer …`.

Ответ должен содержать логические `verified`, `chainValid`, `validNow`, `revocationChecked`, `keyUsageValid` со значением `true`, `revoked: false`, `payloadSha256` точных байтов, `iin`, `name`, `certificateSerial`. Это контракт собственного адаптера CRM; произвольный сервис проверки должен быть приведён к этому контракту. Простого извлечения данных сертификата недостаточно.
