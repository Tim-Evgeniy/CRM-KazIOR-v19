KazIOR CRM v17 — проверка 12.09.2026

ПРОЙДЕНО
• 61 серверных тестов Python: существующие роли/SQLite/заявки/WhatsApp/Telegram/
  документы и 17 новых сценариев v17.
• test_shared_client.cjs: инициализация основной CRM, роли, сохранение,
  конфликты изменений, потерянный ответ после сохранения, повтор операции.
• test_documents_client.cjs: три тестовых документа, согласование и подпись,
  защита повторов, участники, протокол NCALayer.
• test_v17_client.cjs: четыре OAuth-формы, семь каналов WhatsApp, ввод и
  очистка секретов в форме, окно ЭЦП и отмена, категория, почтовая страница.
• Python py_compile и JavaScript node --check для изменённых модулей.

Проверено в сценариях v17:
— обновление профилей и сохранение пароля администратора;
— ФИО/пароль Жайнар, отсутствие выдуманного телефона, образование в справочнике;
— все категории, передача введённых фактов и категорий в помощник;
— OAuth state/cookie/nonce, PKCE, срок, повтор запроса, привязка к провайдеру;
— новый OAuth-аккаунт не получает роль инженера по совпавшему ФИО;
— существующий инженер после явной привязки входит в прежний кабинет;
— почтовое согласие не создаёт привязку входа, проверяются нужные scopes;
— refresh token, скрытие секретов, доступ только владельца ящика;
— дедупликация полученных писем, преобразование HTML в текст;
— отправка с тем же ключом операции не дублируется, тайм-аут блокирует повтор;
— заявка из письма не подменяет аккаунт администратора или телефон инженера;
— NCANode: точные подписанные байты, отзыв, срок, назначение ключа, отказ при
  неверных признаках; первый вход ЭЦП создаёт только сотрудника;
— общий WhatsApp-канал назначает указанному инженеру или инженеру по умолчанию;
— HTTP: открытие новых страниц, cookie обмена, завершение входа, закрытые
  серверные файлы, закрытые почтовые данные, отказ при поддельной ЭЦП.

ЧТО НЕ ПРОВЕРЕНО НА РЕАЛЬНОМ ОБОРУДОВАНИИ / ВНЕШНИХ АККАУНТАХ
• Реальное прохождение OAuth-согласия Google/Яндекс/Mail.ru/Microsoft: реквизиты
  приложений и учётные записи пользователя не предоставлены.
• Получение/отправка реальной почты и сообщений реальным людям не выполнялись.
• Настоящий ключ ЭЦП, запущенный NCALayer и Docker Desktop на Windows пользователя
  не использовались. Протокол и отказы проверены имитациями сервисов.
• Браузерная визуальная проверка этой среды не выполнена: локальный адрес CRM
  недоступен управляемому браузеру. Клиентские проверки используют Node VM и DOM,
  они не подтверждают отображение в реальном Chrome/Яндекс Браузере.
• 700 сотрудников проверены на уровне хранения, 700 одновременных соединений — нет.

Повторить проверки из корня папки:
python -m unittest discover -s tests -p "test_v*.py" -q
node tests/test_shared_client.cjs
node tests/test_documents_client.cjs
node tests/test_v17_client.cjs
Для Node-проверок на Windows замените python3 в tests/client_fixture-вызывающих
скриптах на доступную команду Python, если python3 отсутствует.
