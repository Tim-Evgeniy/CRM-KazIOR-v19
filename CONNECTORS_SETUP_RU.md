# Подключения v17

## Корпоративный вход

На странице входа доступны Google, Яндекс, Mail.ru и Microsoft. Кнопки начинают серверный OAuth-процесс. Для работы сначала нужны реквизиты приложений вашей организации; они не могут быть заменены ключом WhatsApp.

1. Выберите один адрес CRM, например `https://crm.example.kz` в вашей локальной сети или `http://localhost:8000` для одного компьютера.
2. Зарегистрируйте веб-приложение у каждого нужного провайдера. Укажите Redirect URI из таблицы ниже, заменив пример адресом своей CRM.
3. Войдите администратором → **Интеграции → Подключение почты и корпоративный вход**. В соответствующей карточке введите адрес CRM, Client ID и Client Secret, включите вход и сохраните.
4. Вернитесь на страницу входа и нажмите кнопку провайдера. Подтверждение выполняется на сайте провайдера.

| Провайдер | Redirect URI | Доступ для входа |
|---|---|---|
| Google | `https://crm.example.kz/api/oauth/callback/google` | `openid email profile` |
| Яндекс | `https://crm.example.kz/api/oauth/callback/yandex` | `login:info login:email` |
| Mail.ru | `https://crm.example.kz/api/oauth/callback/mailru` | `userinfo` |
| Microsoft | `https://crm.example.kz/api/oauth/callback/microsoft` | `openid profile email User.Read` |

Для Microsoft регистрируйте платформу **Web**. Текущая настройка использует `common`, поэтому тип поддерживаемых аккаунтов приложения должен разрешать нужные организационные и/или личные аккаунты. Указанный Redirect URI должен совпадать с настройкой провайдера.

Google, Яндекс и Microsoft используют PKCE S256; все четыре — одноразовый state, привязанный к HttpOnly-cookie браузера, сроку действия и отдельному nonce. Секреты и почтовые токены не выдаются в браузер. Данные личности запрашиваются сервером у фиксированного API провайдера.

**Чтобы сохранить существующий кабинет инженера**, сначала войдите по ФИО/логину и паролю, затем привяжите нужный аккаунт в «Моём профиле». Новый неподключённый аккаунт создаёт обычного сотрудника. Совпадение email или ФИО само по себе не объединяет кабинеты и не выдаёт права. Привязку можно отключить в профиле.

Документация провайдеров: [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Яндекс — код и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [Яндекс — данные пользователя](https://yandex.ru/dev/id/doc/ru/user-information), [Mail.ru OAuth](https://help.mail.ru/developers/oauth/), [Microsoft authorization code](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow).

## Google / Gmail и Microsoft Outlook / 365

1. Для Google включите Gmail API в проекте приложения. Настройте экран согласия и добавьте нужные тестовые аккаунты, если приложение находится в тестовом режиме. Для распространения ограничения и подтверждение доступа задаёт Google.
2. Для Microsoft добавьте делегированные разрешения `User.Read`, `Mail.Read`, `Mail.Send`, `offline_access`. Если организация ограничивает согласие, его предоставляет администратор Microsoft 365.
3. В CRM откройте **«Почта»** → «Подключить Google» или «Подключить Microsoft». Подтвердите чтение и отправку писем. Это отдельное действие от корпоративного входа; вход сам по себе не подключает ящик.
4. Нажмите «Получить письма». При желании включите обновление каждую минуту, пока открыто окно почты.

Для Gmail запрашиваются `gmail.readonly` и `gmail.send`; для Microsoft — `Mail.Read`, `Mail.Send`, `offline_access`. Токены обновляются сервером при наличии refresh token. При отзыве доступа или истечении разрешения подключите ящик заново.

Используются [Gmail API](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send) и [Microsoft Graph](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0). Ответ о принятии письма почтовым сервером не означает прочтение адресатом.

## Яндекс Почта и Mail.ru

1. В настройках почты разрешите IMAP/SMTP.
2. Создайте пароль приложения для почтовой программы.
3. В CRM → «Почта» нажмите кнопку нужного сервиса, укажите полный email и пароль приложения.
4. CRM проверит соединение с входящим и исходящим сервером без отправки письма. После успешного подключения можно получить письма и ответить.

| Провайдер | Входящие | Исходящие |
|---|---|---|
| Яндекс | `imap.yandex.ru:993`, TLS | `smtp.yandex.ru:465`, TLS |
| Mail.ru | `imap.mail.ru:993`, TLS | `smtp.mail.ru:465`, TLS |

Адреса серверов фиксированы для этих провайдеров. Произвольные внутренние IMAP-серверы в этом выпуске не настраиваются. Если у корпоративного ящика другой сервер, потребуется отдельная адаптация. Mail.ru OAuth служит входу в CRM; сам ящик Mail.ru здесь подключается паролем приложения.

## Работа с письмами

Окно почты показывает последние 200 сохранённых писем. IMAP при первом получении сохраняет последние 50 сообщений INBOX, затем получает новые по UID. Gmail и Microsoft получают INBOX порциями до 500 новых писем за обновление с продолжением страниц при следующем запросе. Удаления и перемещения в исходном ящике не удаляют сохранённую копию CRM. Вложения пока показываются названиями; содержимое вложений открывайте в исходном почтовом сервисе.

Ящик доступен только пользователю, который его подключил. «Отключить ящик» удаляет его ключи и полученные копии из CRM, оставляя оригиналы у провайдера. Ранее созданные заявки сохраняются.

Ответ открывается готовым черновиком с адресом и темой; отправка происходит только по кнопке. После тайм-аута повторная отправка той же операции блокируется: сначала проверьте отправленные письма у провайдера. Для IMAP/SMTP копия в папке «Отправленные» зависит от почтового сервиса; CRM не выполняет отдельный IMAP APPEND. Нельзя гарантировать доставку по одному SMTP-подтверждению.

Инженер может создать заявку из письма, выбрав категорию и указав телефон сотрудника. ФИО берётся из письма, заявка назначается инженеру, который её создал. Автор письма сохраняется отдельным внешним контактом: заголовок From не является подтверждением права войти в существующий кабинет. Ответ из самой заявки не рассылается по email автоматически; для отправки используйте ответ в окне «Почта».

## WhatsApp: общий ключ или личные каналы

В «Интеграциях» выберите канал инженера. Ключ администратора уже подставляется из предоставленного файла. Пустое поле ключа сохраняет прежнее значение; свой ключ можно ввести вручную вместе с `idInstance`.

**Личный номер инженера:** выберите режим «Личный номер инженера». Входящая заявка назначается владельцу канала. Фактический номер проверяется по данным GREEN-API.

**Единый номер отдела:** на одном подключённом номере выберите режим «Единый номер отдела» и инженера по умолчанию. Нужен один инстанс и один его ключ. Команда `Заявка: @elnur описание` назначит Елнуру; без `@логин` — выбранному инженеру по умолчанию. Имена логинов приведены в `START_HERE_RU.md`.

Если нужны сообщения, отправленные на разные личные номера, для каждого такого номера создаётся собственный инстанс. Нельзя указать один idInstance нескольким каналам и получить сообщения со всех номеров. У Жайнар телефон не задан: внесите её реальный номер при подключении.

Сохраните настройки и перезапустите CRM. Приём работает на сервере через исходящие запросы GREEN-API. Webhook или другой параллельный получатель этого инстанса мешает приёму; CRM отображает состояние подключения. Протокол: [GREEN-API receiveNotification](https://green-api.com/en/docs/api/receiving/technology-http-api/ReceiveNotification/).

## Что нужно заполнить на месте

| Функция | Необходимые данные / приложения |
|---|---|
| Корпоративный вход | Client ID, Client Secret и Redirect URI каждого провайдера |
| Gmail / Outlook | OAuth-приложение и согласие владельца ящика на почтовые права |
| Яндекс Почта / Mail.ru | Email, пароль приложения, разрешённые IMAP/SMTP |
| Вход и подпись ЭЦП | NCALayer на рабочем месте, запущенный NCANode на сервере, собственный ключ |
| WhatsApp остальных номеров | Собственные idInstance и ключи подключаемых номеров |
| Telegram | Отдельный BotFather-токен |
| Генеративный AI | Отдельный AI API-ключ; локальные подсказки доступны сразу |

Все серверные и клиентские тесты выполнялись без доступа к реальным почтовым ящикам и закрытым ключам пользователя. Настройки приложений и полноценное прохождение согласия должны быть выполнены владельцем на его рабочем компьютере.
