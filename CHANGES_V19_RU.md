# CRM КазНИИОиР — исправления v19

## Запуск и обновление

Распакуйте весь архив и запустите `START_CRM.bat`. Нужен Python 3.10 или новее; запускатель проверяет его автоматически. Открывать `index.html` двойным щелчком не нужно.

Если уже работает CRM с настоящими заявками: сделайте резервную копию, остановите старый сервер и обновите файлы программы. Сохраните свою папку `data` и файл `server/config.local.json`. В архиве нет рабочей базы и тестовых пользователей. Не запускайте одновременно две копии CRM, принимающие сообщения одного WhatsApp-инстанса.

## Исправлено

- Поиск защищён от автозаполнения логином при входе. Ввод поиска не переключает разделы. Введённый человеком запрос, включая слово `superadmin`, не удаляется самопроизвольно.
- Команда инженеров и справочник отсортированы по ФИО. Новые активные инженеры включаются в команду независимо от заполнения подразделения. Счётчик инженеров соответствует активному составу команды, включая супер-администратора.
- Кнопки редактирования и сброса пароля доступны супер-администратору в списке сотрудников и в команде инженеров. Сервер запрещает изменение чужой учётной записи остальным ролям. Каждый может редактировать свои контакты.
- Реализована отсутствовавшая форма сброса пароля. Пароли от 10 символов, с повторным вводом; прежние сеансы завершаются. Для сотрудника новый пароль позволяет войти по его логину через форму входа с паролем.
- Исправлено сохранение локации профиля. Формы профиля и учётных записей показывают успех только после ответа сервера.
- Светлая и тёмная темы доступны на странице входа. Выбор сохраняется отдельно от персональной темы кабинета. Исправлен контраст текста в светлой теме.
- Кнопка текущего статуса открывает четыре явных варианта: Доступен, Занят, Отошел, Не беспокоить.
- NCALayer: добавлен обязательный параметр выбора сертификата, обработка вариантов успешного ответа, быстрый тайм-аут соединения и запасной адрес localhost. Отмена и ошибка ключа не запускают повторное окно. Проверка подключения не подписывает данные и не запрашивает ключ.
- Сервер теперь отдаёт `v18-ui.js`: ранее файл помощника был указан в HTML, но отсутствовал в списке разрешённых ресурсов. Обновлён кэш приложения.

## WhatsApp

В «Интеграциях» сохраните настройки канала. Они применяются без перезапуска всей CRM. Есть отдельные кнопки «Проверить подключение», «Применить без перезапуска CRM» и «Отправить тест на этот номер».

Для инстанса 7103540119 используется адрес `https://7103.api.greenapi.com`. Прежний ключ из предоставленного архива сохранён в приватной серверной настройке; в браузер и результаты диагностики он не возвращается. Существующая `config.local.json` имеет приоритет при обновлении: проверьте адрес API в ней через форму настроек.

Новая веб-заявка получает канал WhatsApp по привязке сотрудника, общему номеру отдела или доступному каналу. Ответы и статусы отправляются на телефон, указанный в заявке, в том числе для старых заявок при следующем ответе. Текст содержит номер, тему, статус, инженера и подпись IT-System-Solution / www.its24.kz. Контактный номер необходимо указывать верно.

Уведомление диспетчеру больше не зависает лишь из-за того, что подключён один канал с тем же номером. Отправка проходит через постоянную очередь. Подтверждение сервиса и фактическая доставка отображаются отдельно; неопределённые результаты не отправляются повторно автоматически.

Два режима входящих сообщений:

1. Для личного номера инженера: `Заявка: не работает принтер`. Ответ — с номером `KZ-000001` или цитированием сообщения заявки. Остальная личная переписка пропускается.
2. Для выделенного номера Service Desk можно выбрать «Каждое личное сообщение». Обычный текст создаёт обращение; если в этом чате ровно одна открытая заявка, последующий текст добавляется ответом. При нескольких заявках нужно указать номер или ответить цитатой. Новую отдельную проблему начинайте со слова `Заявка:`.

Флажки уведомлений управляют новыми заявками инженерам, ответами сотруднику и изменениями статуса. Уведомления и переписка внутри CRM сохраняются независимо от WhatsApp.

## Что проверено и что осталось подключить

- Серверные проверки выполнялись на временных базах, клиентские — с тестовыми транспортами. Настоящие заявки и пароли сотрудников не изменялись.
- В браузере проверены вход, светлая тема, поиск, алфавитный список, счётчики, форма сброса пароля, выбор доступности и элементы диагностики.
- Реальный NCALayer на этом компьютере успешно ответил на проверку из браузера. Закрытый ключ не выбирался и подпись не выполнялась.
- Реальный GREEN-API ответил `authorized`; номер совпал, необходимые флаги уведомлений включены, webhookUrl пуст. Реальные тестовые сообщения сотрудникам не отправлялись. Для проверки доставки укажите свой номер и воспользуйтесь кнопкой теста; дождитесь состояния «Доставлено» в журнале.
- Полный вход по ЭЦП требует серверной проверки подписи NCANode. В данной среде Docker и слушающий NCANode на порту 14579 не обнаружены. Инструкция установки и включения — `EDS_SETUP_RU.md`. Одного NCALayer для проверки подлинности на сервере недостаточно.
- Генеративный AI не подключён: решение по API-ключу не получено. Существующие локальные подсказки сохранены. Облачная генерация и консультация по настоящему API не проверялись.

Исходники протоколов: [НУЦ: KNCA Basics](https://github.com/pkigovkz/sdkinfo/wiki/KNCA-Basics-Module), [GREEN-API: отправка](https://green-api.com/docs/api/sending/SendMessage/).
